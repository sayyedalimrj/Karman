# بخش ۸ - نقشه قوانین محاسباتی و تجاری تکسا

## وضعیت

- [x] انجام شد

## اصل کلیدی

قوانین نسخه وب نباید فقط از روی PDF یا فقط از روی دیتابیس نوشته شوند. منبع معتبر برای هر قانون باید ترکیبی از سه لایه باشد:

1. **سند رسمی/PDF** برای متن قانونی و شرایط اعمال.
2. **دیتابیس/ویو/پروسیجر تکسا** برای منطق اجرایی و داده مرجع.
3. **خروجی واقعی تکسا، SVZT، Excel یا RPT** برای تست تطبیق و round-trip.

## نتیجه محصولی

UI و workflow نسخه وب می‌تواند بهتر، خوشگل‌تر و قابل‌فهم‌تر از تکسا باشد، اما نباید منطق داده‌ای و خروجی‌های قابل برگشت را خراب کند. هر صفحه وب باید پشت خودش یک projection قابل گزارش و یک patch plan برای export داشته باشد.
