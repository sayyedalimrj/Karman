# بخش ۷ — تحلیل Excel و قالب‌های خروجی تکسا

## وضعیت

## منابع بررسی‌شده
- `Fosool.xls` — قالب خلاصه فصل‌ها / مبلغ فصل با احتساب ضرایب
- `kholaseh_metreh.xls` — قالب خلاصه متره و اتصال به صورت‌مجلس / ملاحظات / شرح آیتم
- `Mali.xls` — قالب برگه مالی / آیتم‌های مالی فهرست‌بها با مقدار کارکرد و مقدار برآوردی
- `Rizmertreh.xls` — قالب ریزمتره تفصیلی با ابعاد تعداد/طول/عرض/ارتفاع/وزن و شرح عملیات
- `rzmt_act.xls` — قالب ریزمتره مرتبط با فعالیت‌ها؛ مشابه ریزمتره ولی دارای کد فعالیت
- `resource_price.xlsx` — قالب ورود قیمت روز منابع/عوامل به فرم منابع پروژه
- `FaragamTemplate.mpp` — قالب Microsoft Project برای map خروجی زمان‌بندی به Excel و خواندن در تکسا
- `read_msp.txt` — راهنمای استفاده از FaragamTemplate.mpp و map خروجی MSP به Excel

## خلاصه اجرایی
قالب‌های Excel تکسا در این بخش بیشتر نقش «ورودی/خروجی استاندارد و قابل کپی» دارند، نه موتور اصلی محاسبات. در فایل‌های `.xls` بررسی‌شده، رکورد فرمول قابل اتکا پیدا نشد؛ بنابراین منطق محاسباتی باید از دیتابیس، view/procedureها، PDFهای قوانین و فایل SVZT استخراج شود، اما خروجی‌های وب باید از نظر ستون، ترتیب، نوع داده و ساختار با این قالب‌ها سازگار بمانند.

## کشف‌های مهم
1. `Rizmertreh.xls` قالب ریزمتره تفصیلی است و ستون‌های ابعادی `تعداد/طول/عرض/ارتفاع/وزن یا .../جمع جزیی` دارد.
2. `rzmt_act.xls` همان ریزمتره را با ستون اضافه `کد فعالیت` توسعه می‌دهد؛ پس نسخه وب باید ریزمتره فعالیت‌محور را جدا بشناسد.
3. `kholaseh_metreh.xls` به صورت‌مجلس وصل است؛ ستون‌های `شماره صورتمجلس` و `تاریخ صورتمجلس` برای اتصال مستندات اجرایی مهم‌اند.
4. `Mali.xls` ستون‌های مالی مهم مثل `مقدار کارکرد`، `مقدار برآوردی`، `بهای واحد پایه` و `بهای واحد پیشنهادی` دارد و برای برگه مالی/صورت‌وضعیت حیاتی است.
5. `Fosool.xls` خروجی خلاصه فصل با `مبلغ فصل بااحتساب ضرایب` را مشخص می‌کند؛ پس موتور ضرایب باید قبل از خروجی فصل‌ها اعمال شود.
6. `resource_price.xlsx` صراحتاً توضیح می‌دهد قیمت روز منابع با انتخاب ستون‌های کدعامل و بهای واحد و دریافت از حافظه وارد فرم منابع پروژه می‌شود؛ پس نسخه وب باید importer با تطبیق کدعامل داشته باشد.
7. `FaragamTemplate.mpp` و `read_msp.txt` نشان می‌دهند تکسا با Microsoft Project تبادل دارد؛ این باید به عنوان فاز Integration جدا ثبت شود.

## الزامات نسخه وب
- **EXCEL-001**: تمام قالب‌های xls/xlsx باید در نسخه وب به عنوان Template Registry ثبت شوند، نه فایل‌های پراکنده. دلیل: هر قالب نقش مشخصی در import/export دارد.
- **EXCEL-002**: نام و ترتیب ستون‌ها در export باید دقیقاً با قالب تکسا حفظ شود. دلیل: تکسا/کاربر با copy/paste یا import به ترتیب ستون وابسته است.
- **EXCEL-003**: فیلدهای عددی باید numeric واقعی باشند، نه متن فارسی‌سازی‌شده. دلیل: محاسبه و import دوباره نیازمند عدد واقعی است.
- **EXCEL-004**: خروجی‌های فارسی باید RTL، فونت فارسی، و قالب چاپی قابل قبول داشته باشند. دلیل: نسخه وب باید UI/خروجی تمیزتر از تکسا ارائه کند.
- **EXCEL-005**: resource_price.xlsx باید import wizard داشته باشد: upload/paste، match کدعامل، پیش‌نمایش اختلاف، تأیید نهایی. دلیل: خود فایل توضیح می‌دهد کپی قیمت بر اساس کد عامل مشترک انجام می‌شود.
- **EXCEL-006**: ریزمتره و ریزمتره فعالیت‌محور باید دو حالت جدا داشته باشند. دلیل: rzmt_act.xls ستون کد فعالیت اضافه دارد.
- **EXCEL-007**: خلاصه متره باید اتصال به صورت‌مجلس را نگه دارد. دلیل: kholaseh_metreh.xls ستون شماره و تاریخ صورت‌مجلس دارد.
- **EXCEL-008**: MS Project integration باید به عنوان فاز جدا دیده شود، نه بخشی از MVP صورت‌وضعیت. دلیل: FaragamTemplate.mpp و read_msp workflow جداگانه دارند.
- **EXCEL-009**: برای round-trip، export باید تست snapshot روی header و نوع داده داشته باشد. دلیل: تغییر کوچک در header/order می‌تواند import تکسا را خراب کند.

## اثر روی نقشه محصول
- باید یک `Excel Template Registry` داشته باشیم.
- خروجی‌های Excel باید هم زیباتر باشند، هم header/order/type سازگار با تکسا را حفظ کنند.
- import قیمت منابع و ریزمتره باید Wizard داشته باشد.
- ریزمتره، خلاصه متره، برگه مالی و خلاصه فصل‌ها باید خروجی MVP باشند.
- MS Project integration فعلاً MVP نیست ولی باید در معماری جا داشته باشد.
