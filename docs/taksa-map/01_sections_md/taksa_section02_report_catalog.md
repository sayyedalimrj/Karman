## نتیجه اجرایی

گزارش‌ها نشان می‌دهند تکسا فقط یک ورود داده ساده نیست؛ یک سیستم گزارش‌ساز جدی دارد. نسخه وب باید از ابتدا با تفکیک زیر طراحی شود:

1. صفحه عملیاتی برای کاربر.
2. موتور محاسبه و data model پشت صفحه.
3. خروجی چاپی/PDF/Excel معادل گزارش تکسا.
4. تست تطبیق عددی با گزارش تکسا.

در این بخش هنوز وارد محتوای داخلی فایل‌های `.rpt` نشده‌ایم. تحلیل فعلی بر اساس نام‌گذاری، پوشه‌ها، فراوانی و الگوی گزارش‌هاست. معنی دقیق چند token در بخش‌های بعدی با دیتابیس، `gws.ini` و در صورت نیاز نمونه RPT تثبیت می‌شود.

## ۷. تصمیم طراحی برای نسخه وب

نسخه وب نباید ۱۶۰۶ گزارش را عیناً در UI نمایش دهد. باید این مدل را داشته باشد:

```text
Report Template Registry
  ├── reportKey
  ├── module: estimate | proposal | payment | adjustment | priceList | index | transport
  ├── dataSource
  ├── calculationEngine
  ├── outputType: pdf | excel | print | table
  ├── templateVariant: standard | land | port | shahrdari | naftgaz | custom
  └── compatibilityNames: original RPT names
```

بنابراین در UI کاربر، گزارش‌ها اینطوری نمایش داده شوند:

```text
گزارش‌های صورت‌وضعیت
  - برگه مالی
  - خلاصه فصل‌ها
  - ریزمتره
  - ریز آیتم‌ها / نوت
  - تعدیل
  - ضرایب

گزارش‌های برآورد
  - برگه مالی برآورد
  - خلاصه فصل‌ها
  - آنالیز بها
  - پیمان/فهرست آیتم‌ها

گزارش‌های پایه
  - فهرست‌بها
  - شاخص‌ها
  - ضرایب
  - فاصله/حمل
```
